# Contributing

Keep changes focused. Explain the problem, resulting behavior, and validation in your pull request. Run the validator and installer tests. For instruction changes, run relevant behavioral cases in OpenCode and include redacted outputs, OpenCode version, provider/model, and rubric results. Do not submit credentials or private repository content.

Prefer durable guidance over model-specific claims. Do not claim improved quality or lower cost without reproducible measurements. Add behavioral fixtures for failure modes; structural checks alone cannot establish instruction quality.
